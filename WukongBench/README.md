# WukongBench

Консольный инструмент на C#, который автоматически прогоняет **Black Myth: Wukong Benchmark Tool** (Steam AppID 3132990) дважды — с настройками под CPU и под GPU — и выводит отчёт: характеристики ПК, результаты обоих проходов и использованные настройки.

## Требования

- Windows 10/11 x64, [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0).
- Запущенный Steam и установленный Black Myth: Wukong Benchmark Tool.
- Бенчмарк хотя бы один раз запущен вручную до главного меню: при первом запуске он создаёт файл настроек и спрашивает согласие на сбор данных. Это решение пользователя, инструмент его не принимает.

## Запуск

```
dotnet run --project src/WukongBench -c Release
```

Дальше всё происходит само: инструмент находит бенчмарк, применяет настройки, запускает тест, ждёт результата и повторяет то же для второго прохода. Один проход занимает около трёх минут. Во время работы не трогайте мышь и клавиатуру: тест запускается эмуляцией ввода в окне игры.

Отчёт печатается в консоль и сохраняется в `results/<дата_время>/report.md`; рядом лежат исходные файлы результатов бенчмарка `cpu_raw.json` и `gpu_raw.json`.

| Ключ | Назначение |
|---|---|
| `--path <папка>` | Папка установки бенчмарка, если он не находится через Steam |
| `--only cpu\|gpu` | Выполнить только один проход |
| `--no-rt` | Не включать полную трассировку лучей в GPU-тесте |
| `--timeout <минуты>` | Предел ожидания одного прохода, по умолчанию 15 |
| `--menu-point <x,y>` | Координаты пункта «Тест быстродействия» в раскладке 1920×1080, по умолчанию `220,484` |
| `--out <папка>` | Куда сохранять отчёты, по умолчанию `results` |

Тесты ядра: `dotnet test tests/WukongBench.Core.Tests`.

## Как это работает

У Benchmark Tool нет ни параметров командной строки, ни API, поэтому способ управления пришлось определить по его файлам.

1. **Поиск.** Путь к Steam берётся из реестра, библиотеки — из `steamapps\libraryfolders.vdf`, папка бенчмарка — из `appmanifest_3132990.acf`.
2. **Настройки.** Бенчмарк читает их при старте из `<папка>\b1\Saved\Config\Windows\GameUserSettings.ini`. Выбор из меню хранится одной строкой `UISettingData=(("Ключ", "Значение"),...)`, а секция `[ScalabilityGroups]` дублирует его для движка (`sg.* = значение меню − 1`). Инструмент меняет только нужные ключи в обоих местах, пока игра закрыта; остальное содержимое файла, его кодировка и переводы строк сохраняются.
3. **Запуск.** Бенчмарк стартует через `steam://rungameid/3132990`. Сам тест запускается эмуляцией ввода (`SendInput`): Enter на заставке, клик по пункту «Тест быстродействия», Enter в диалоге подтверждения. Во время теста Enter и левый клик игнорируются, поэтому последовательность безопасно повторяется, пока не появится результат, и распознавание экрана не требуется. Координаты пункта меню масштабируются по высоте окна, как и интерфейс игры.
4. **Результат.** По завершении бенчмарк пишет JSON в `%TEMP%\b1\BenchMarkHistory\Tool\<unix-время>`. Появление нового файла — сигнал окончания прохода. Из него берутся средний, минимальный и максимальный FPS, 5% low, загрузка CPU и GPU, занятая видеопамять и массив `Records` с покадровой телеметрией, по которому дополнительно считаются 1% low и средние времена кадра.
5. **Завершение.** Процесс игры завершается принудительно: при штатном выходе игра перезаписала бы файл настроек. Исходный `GameUserSettings.ini` копируется в `%LOCALAPPDATA%\WukongBench` и возвращается на место после прогонов, в том числе при ошибке и по Ctrl+C. Если инструмент был убит, настройки восстановятся при следующем запуске.

Характеристики ПК собираются через WMI: процессор, ядра и потоки, видеокарты с объёмом памяти и версией драйвера, объём и частота ОЗУ, ОС, материнская плата, режим дисплея.

## Выбор настроек

Общее для обоих проходов: VSync и ограничение FPS выключены, генерация кадров выключена, апскейлер TSR. Без этого FPS упирается в частоту монитора или завышается сгенерированными кадрами и перестаёт отражать производительность железа. TSR выбран потому, что работает на видеокартах любого производителя.

### CPU-тест

Цель — чтобы кадр ограничивал процессор, а видеокарта простаивала.

| Настройка | Значение | Почему |
|---|---|---|
| Качество, все группы | Низкое | Минимум работы для GPU; нагрузка на CPU (логика, анимация, подготовка draw calls) остаётся |
| Масштаб рендера | 33% | Минимум, который разрешает меню: пикселей примерно в 9 раз меньше, чем при 100% |
| Полная трассировка лучей | Выкл | Самая тяжёлая для GPU опция |
| Размытие в движении | Выкл | Лишний проход постобработки |

### GPU-тест

Цель — максимальная нагрузка на видеокарту.

| Настройка | Значение | Почему |
|---|---|---|
| Качество, все группы | Кинематографическое | Максимум теней, Lumen, отражений, текстур и растительности |
| Масштаб рендера | 100% | Рендер в полном разрешении без апскейла |
| Полная трассировка лучей | Вкл, максимальный уровень | Path tracing нагружает GPU сильнее всего; включается только на NVIDIA RTX, где игра его поддерживает |
| Размытие в движении | Сильное | Дополнительный проход постобработки |

Разрешение экрана инструмент не меняет: используется то, что уже выбрано в бенчмарке (по умолчанию нативное). Нагрузкой на GPU управляет масштаб рендера, и результат не зависит от списка режимов конкретного монитора.

Проверить, что настройки сработали, можно по самому отчёту: в нём выводится средняя загрузка GPU по данным бенчмарка. В CPU-тесте она должна быть заметно ниже 100%, в GPU-тесте — около 100%. Там же выводятся настройки, которые бенчмарк сам записал в файл результата.

## Ограничения

- Только Windows и только основной монитор.
- Координаты пункта меню подобраны для формата 16:9. Если на другом формате тест не стартует, их можно задать ключом `--menu-point`.
- Формат файлов бенчмарка не документирован и может измениться с обновлением.

## Структура

```
src/WukongBench.Core   логика без привязки к Windows: ini, профили, разбор результата, отчёт
src/WukongBench        Windows-часть: Steam, эмуляция ввода, WMI, точка входа
tests/                 модульные тесты ядра (xUnit)
```
